Store Release Toolkit

From store setup to a clean local build

Configure Steam or Epic packaging, validate the project, and create a Windows x64 folder for separate storefront delivery.

1. Setup

Open Window > Store Release Toolkit. The Setup page detects Steamworks.NET and the EOS Plugin. If one is missing, use its Download button to install the supported package into the current project.

  • Set the executable, icon, default version, and output templates.
  • Set the public Steam App ID for Steam builds.
  • Set Epic product, sandbox, deployment, EOS client, encryption, templates, and bootstrapper values.
  • Use the built-in actions to create project-local EOS templates.

The toolkit never requests a developer username, password, or storefront credential.

2. Add achievement calls

Define project-owned IDs that match Steam and Epic, then use the store-neutral runtime API.

using Aroko.StoreRelease.Runtime;
StoreAchievements.Unlock(GameAchievementIds.FirstWin);

Pending unlocks persist and retry automatically through the provider selected for the build.

3. Validate and build

  1. Select a Steam or Epic profile and version.
  2. Review the resolved output folder.
  3. Run Validate Configuration.
  4. Run Build Windows x64.
  5. Inspect the report and generated folder.

During the build, the inactive vendor plugin is temporarily disabled and restored afterward. The output is checked for inactive-store contamination.

4. Build checklist

  • Required vendor SDK is detected.
  • Version, scenes, icon, executable, and output path are correct.
  • Epic packaging values or Steam App ID validate.
  • Diagnostics has no blocking issues.
  • The build contains only the selected store integration.

5. CI

-executeMethod Aroko.StoreRelease.Editor.StoreReleaseCli.Run
-srtAction validate|build
-srtProfile <profile-id>
-srtVersion <version>
-srtReport <report.json>

Archive the generated folder as the CI artifact. The toolkit has no storefront-delivery action.
